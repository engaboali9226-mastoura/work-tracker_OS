# Local management changes r82

- Person files expose principal and individual repayment editing. Corrections require a reason and the version token captured when the dialog opened. Previous values remain in the correction history. Currency, direction and cash account remain fixed. Existing ownership, conditional ledger revisions and request idempotency apply. Negative cash, debt below paid total, overpayment, future dates and invalid payment ordering are rejected.
- Habit cards group all non-archived definitions by trimmed category, including continuous, limited, future, expired and paused habits. Non-due habits remain visible but cannot be completed. Daily progress uses due executions only. Existing schedule semantics are preserved.
- Habits have an optional local HH:mm time, prefilled during editing and shown in category rows. Medicines/supplements are included in default categories. This is one time per habit, without notification delivery, dosage guidance or a time-based completion restriction.
- Dashboard completion, notes and task progress render optimistically. Each execution is locked while pending; different executions queue serially. Authoritative replies reconcile the view. Failed writes roll back that change and retain the command, note and amount for explicit retry. Pending/failed writes are held in memory, not durable offline storage. A beforeunload warning protects pending saves; closing the page can still lose unconfirmed inputs. Financial amounts are confirmed before displaying success.
- The local installer tests an external copy, backs up touched files, installs source and compiled personal/runtime modules, and performs no commits, pushes, merges, deployments, schema changes or user data commands. It never starts or stops local servers. Restart the existing local runtime to load changed backend code. Existing frontend HMR can load the UI after source installation.
