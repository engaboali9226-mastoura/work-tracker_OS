- Offline validator accepts exact known v1 envelope and event-type-specific payload with fail-closed checks, owner scope, duplicate detection and count-only diagnostic projection. Unknown future versions require explicit schema review. Counts describe existing records, not achievements. - Retention contract: archive versus permanent deletion are distinct. Explicit approved permanent deletion must remove linked historical facts and recompute affected analytics; removal from a snapshot without trusted deletion provenance is a conflict requiring reconciliation, never silently accepted. Keep no private contents in diagnostics. Identity-linked metadata remains personal data. No free-text journals, finance, moods, student data in analytics by default.
- Production acceptance of validator still requires exact whole-row read-only validation inside database (or restricted staging restore) and compatibility review beyond metadata. Tests use synthetic data only. No user data transferred; no production changes.
