## Required fact contract for future analytics
- Operational state remains authoritative. Capture future facts transactionally from canonical execution/activity/day and approved policy snapshot, not from legacy event counts.
- For every fact retain owner scope, execution/activity identity, source revision, fact schema version, due civil date and authoritative day timezone, performance local date plus provenance (explicit / legacy recovery / observed activity / unknown), evaluation instant, effective weight/credit and policy version where evidenced. Unknown stays null, not zero and not silently excluded. Never infer historical weight from current definition alone.
- Existing completion-r331.ts chooses R367 linear deduction for explicit completion dates, legacy R331 for recovery-only dates, and current normal completed-share otherwise. Prayer projection uses trusted context and approved snapshot; aggregate raw weight/earnedWeight before rounding. Session/activity eligibility rules stay in the existing domain implementation. New history must NOT change or recompute baseline outputs implicitly.
- Define distinct due-day achievement vs actual-day activity, with separate denominators and explicit quality coverage. No double counting of sessions, retries or recovered items. Preserve versioned corrections and permanent deletion in both fact storage and derived aggregates. No private content dimensions by default.
- Before backfill: exact source/target revision and identity parity, approved privacy/minimization and retention policy, parity fixture tests against unchanged existing daily/weekly/monthly projection, and restore/rollback evidence. This report measures coverage only, not productivity or release readiness.
